# LazyEdge v0.4.0

v0.4.0 adds security primitives for application-owned rollout controllers while
keeping LazyEdge independently useful as a default-deny transport layer. The new
CLI commands are read-only; this release does not add a deployment executor or
change an existing `EdgeProject`, listener, route, service, or credential.

## What changed

- Added the strict `EdgeRollout` `v1alpha1` contract for one to 256 exact
  regular-file claims and a deterministic plan digest.
- Added read-only `lazyedge rollout validate`, `plan`, and `inspect` commands.
- Added a durable adjacent-phase activation/rollback journal with sequence CAS,
  exclusive process-instance leases, verified stale-owner reclamation, and
  immutable terminal receipts.
- Added short-lived one-shot stop permits bound to the plan, operation, service
  unit, systemd `InvocationID`, PID, Linux process start ticks, unit digest,
  listeners, admission generation, and proof digest.
- Exported the contract, journal, stop-authority library, and JSON Schema through
  explicit npm package subpaths.

## Security hardening

- Public and nested envelopes require exact own enumerable data properties;
  inherited fields, accessors, symbols, unknown properties, prototype pollution,
  sparse arrays, custom iterators, and fabricated phase histories fail closed.
- The rollout loader reads at most 1 MiB plus one byte from a stable regular-file
  handle and rejects symlinks, invalid UTF-8, duplicate keys, aliases, YAML merges,
  custom tags, parser warnings, multiple documents, and pathname replacement.
- Journal and permit records require exact Unix identity, private modes, regular
  files, one-link records, durable publication, and stable directory ancestry.
  Writable ancestors are accepted only with sticky-bit rename protection.
- Stop authority rechecks expiry and PID/start-ticks identity before and after
  durable one-shot consumption. Consuming a permit never calls systemd.

## Ownership boundary

The application controller still owns artifact hashing and installation, live
service discovery, systemd/DBus `InvocationID` verification, readiness and drain
predicates, admission fencing, route changes, process stops, acceptance, and
rollback. The stores trust code running as the same effective Unix UID and root;
they are not distributed signatures or protection from a compromised account.

## Upgrade and rollback

The new surface is additive. Existing v0.3.1 manifests and runtime processes do
not require migration or restart. Review and pin the exact v0.4.0 package before
embedding the new libraries. To roll back the CLI/library, reinstall the exact
v0.3.1 artifact; no LazyEdge-managed service or data conversion is required.
