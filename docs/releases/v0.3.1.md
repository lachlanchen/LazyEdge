# LazyEdge v0.3.1

v0.3.1 adds an opt-in, bounded LocalLLM application-admission profile while
preserving LazyEdge's transport-only ownership boundary. Existing
`localllm-openai` manifests and their inference routes are unchanged.

## What changed

- Added `profile: localllm-openai-admission`, which requires the exact
  authenticated claims `GET /readyz` and `GET /api/node/capabilities` in
  addition to an explicitly selected subset of the existing `/v1` routes.
- Added a worker-side doctor predicate that separates transport reachability
  from application admission. Legacy `/healthz` remains transport-only and can
  never admit a node.
- Bounded both admission documents to 256 KiB and required exact HTTP 200,
  JSON, and `Cache-Control: no-store` responses.
- Required matching immutable release IDs, fresh passing role canaries,
  supported protocol claims, and exact model digest/provenance agreement.
- Rejected malformed, stale, failed, future-dated, release-mismatched,
  model-mismatched, oversized, or reusable-release evidence.

## Ownership boundary

LazyEdge validates a node-admission predicate. It does not enroll nodes, retain
capabilities, choose assignments, drain traffic, migrate sessions, or own
removal state. Those decisions belong to a separate coordinator and require
their own durable state and rollback contract.

## Upgrade and rollback

The new profile is opt-in. Upgrading the executable without changing a manifest
does not publish an additional route or alter an existing service. Before
promoting a service to the admission profile, stage the exact v0.3.1 artifact
on edge and worker, render and review both roles, run `doctor --role worker`,
and require both `boundaries.transport.ok` and
`boundaries.applicationAdmission.ok`. Keep the exact v0.3.0 executable and its
last accepted manifest as the immediate rollback target.
